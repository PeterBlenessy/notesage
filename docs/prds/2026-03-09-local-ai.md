# PRD: Local AI — Bundled Inference with Zero Setup

**Date:** 2026-03-09 **Phase:** 9 **Status:** Complete

---

## Problem

Notesage's AI features currently require users to either:

1. **Pay for a cloud API** (Anthropic, OpenAI) — requires account creation, billing setup, and API key management
2. **Install Ollama separately** — requires terminal comfort, understanding of model management, and a separate background service
3. **Have a Copilot subscription** — limited to inline completions only

This creates a barrier for the majority of users who want AI assistance but don't want to manage external services. A note-taking app should offer useful AI capabilities out of the box — like how whisper-rs already provides on-device transcription without any external dependency.

**Why now:** The llama.cpp ecosystem is mature enough to bundle reliably. Consumer Macs (even 8GB models) can run useful small language models. The existing provider architecture (`AIProvider` interface, connections/routing system) is designed to absorb new providers transparently.

---

## Goals

1. **Zero-config AI:** Users get working AI features on first launch — no API keys, no external software, no accounts
2. **Privacy by default:** All inference happens on-device. No data leaves the machine unless the user explicitly configures a cloud provider
3. **Guided model management:** Auto-detect available RAM, recommend appropriate models, download with progress feedback — same UX pattern as Whisper model management
4. **Transparent integration:** Local AI works through all existing AI surfaces (chat, bubble menu actions, inline completions) with no UI changes to those surfaces
5. **Coexistence:** Local AI runs alongside cloud providers. Users can route different use cases to different engines (e.g., local for quick edits, Claude for complex chat)

## Non-Goals

- **Training or fine-tuning models** — inference only
- **Bundling model weights in the installer** — models download on first use (keeps installer small)
- **Replacing cloud providers** — local AI is an addition, not a replacement
- **Embeddings and semantic search** — deferred to a future phase (foundation laid but not shipped)
- **Windows/Linux support in this phase** — macOS first (Apple Silicon + Intel), other platforms follow
- **Custom model import** — users who want arbitrary GGUF models can use Ollama; bundled experience focuses on curated models

---

## User Stories

**First-time user:**

> As a new user with no AI providers configured, I want to start using AI features immediately, so that I can experience Notesage's AI capabilities without setup friction.

**Privacy-conscious user:**

> As someone who doesn't want my notes sent to cloud APIs, I want fully offline AI, so that I can get writing assistance without data leaving my machine.

**Resource-aware user:**

> As a user with an 8GB MacBook Air, I want the app to recommend a model that fits my hardware, so that I don't accidentally download something that makes my machine unusable.

**Power user with existing setup:**

> As someone who already uses Ollama with large models, I want to keep using Ollama for chat while the bundled engine handles quick inline completions, so that I get the best of both worlds.

**Model management:**

> As a user who started with the small default model, I want to upgrade to a larger model for better quality, so that I can improve AI responses as I see fit.

## Technical Approach

### Architecture: llama-server as Tauri Sidecar

Bundle pre-built `llama-server` binaries from llama.cpp as Tauri sidecars. This is preferred over library embedding because:

- **Process isolation** — a crash in llama-server doesn't crash the app
- **No C++ build complexity** — pre-built binaries, no toolchain requirements in CI
- **OpenAI-compatible API** — same interface as Ollama, minimal frontend changes
- **Independent updates** — can ship new llama-server versions without full app releases
- **Proven pattern** — multiple Tauri apps already use this approach

The sidecar exposes an OpenAI-compatible HTTP API on localhost. A new `LocalProvider` routes through this API using the same interface as `OllamaProvider`.

### Model Management

Reuse the existing Whisper model management pattern:

- Models stored in `~/.notesage/models/llm/`
- Downloaded from Hugging Face in GGUF format
- Progress events via Tauri event system
- Concurrent download support with cancel signals
- Settings UI for model management (download, delete, set default)

### Provider Integration

New `LocalProvider` implementing the existing `AIProvider` interface. Registered as a `local_bundled` auth type in the connections system. Routes through the bundled llama-server's `/v1/chat/completions` endpoint.

```
Connection flow:
  User enables Local AI → model downloads → llama-server starts →
  LocalProvider connects to localhost:PORT → ready for use
```

### Lifecycle Management

- **Startup:** If local AI is enabled and a model is downloaded, start llama-server automatically
- **Shutdown:** Graceful stop on app exit via `RunEvent::Exit` hook (same pattern as ACP agent cleanup)
- **Crash recovery:** Health check endpoint, auto-restart on failure (max 3 retries)
- **Resource management:** Stop llama-server when switching to cloud-only providers

## Data Model

### Rust Backend

**New file:** `src-tauri/src/commands/local_inference.rs`

```rust
// Managed state for the local inference server
pub struct LocalInferenceState {
    process: Mutex<Option<Child>>,           // llama-server subprocess
    port: Mutex<u16>,                        // Assigned localhost port
    models_dir: PathBuf,                     // ~/.notesage/models/llm/
    download_cancels: Mutex<HashMap<String, Arc<AtomicBool>>>,
}

// Tauri commands
#[tauri::command]
pub async fn start_local_server(
    app: AppHandle,
    state: State<'_, LocalInferenceState>,
    model_path: String,
    context_length: Option<u32>,
    gpu_layers: Option<i32>,
) -> Result<u16, String>  // Returns the port number

#[tauri::command]
pub async fn stop_local_server(
    state: State<'_, LocalInferenceState>,
) -> Result<(), String>

#[tauri::command]
pub async fn get_local_server_status(
    state: State<'_, LocalInferenceState>,
) -> Result<ServerStatus, String>

#[tauri::command]
pub async fn list_local_models(
    state: State<'_, LocalInferenceState>,
) -> Result<Vec<LocalModelInfo>, String>

#[tauri::command]
pub async fn download_local_model(
    app: AppHandle,
    state: State<'_, LocalInferenceState>,
    model_id: String,
) -> Result<(), String>

#[tauri::command]
pub async fn cancel_local_model_download(
    state: State<'_, LocalInferenceState>,
    model_id: String,
) -> Result<(), String>

#[tauri::command]
pub async fn delete_local_model(
    state: State<'_, LocalInferenceState>,
    model_id: String,
) -> Result<(), String>

#[tauri::command]
pub async fn get_system_memory() -> Result<SystemMemoryInfo, String>

// Structs
pub struct ServerStatus {
    pub running: bool,
    pub port: Option<u16>,
    pub model: Option<String>,
    pub memory_usage_bytes: Option<u64>,
}

pub struct LocalModelInfo {
    pub id: String,              // e.g., "qwen3-4b"
    pub name: String,            // e.g., "Qwen3 4B"
    pub filename: String,        // e.g., "qwen3-4b-q4_k_m.gguf"
    pub size_bytes: u64,         // Download size
    pub ram_required_bytes: u64, // Approximate RAM needed at runtime
    pub downloaded: bool,
    pub description: String,     // e.g., "Good quality, works well on 16GB Macs"
    pub huggingface_url: String, // Download URL
}

pub struct SystemMemoryInfo {
    pub total_bytes: u64,
    pub available_bytes: u64,
}
```

## Out of Scope (Deferred)

- **Embeddings and semantic search** — `fastembed` integration deferred to future phase. Foundation (model directory structure) is laid.
- **RAG over local documents** — depends on embeddings
- **Local inline completions** — replacing Copilot LSP with local model for ghost text. Possible with the same llama-server but needs separate optimization work.
- **Windows/Linux** — macOS-only in this phase. llama-server binaries exist for all platforms, so extending is straightforward.
- **Custom GGUF model import** — users can use Ollama for arbitrary models
- **Quantization options** — ship Q4_K_M only; additional quantization levels add UI complexity without clear user benefit
- **Multi-model simultaneous loading** — one active model at a time to keep resource usage predictable
- **Auto-update of llama-server binary** — updates ship with app releases
- **Model recommendations based on document type** — use the same model for all tasks

## Implementation Notes

### Port Management

Use ephemeral port assignment (bind to port 0, read assigned port) to avoid conflicts with other local services. Store assigned port in `LocalInferenceState`.

### Process Cleanup

Follow the same pattern as ACP agent cleanup:

- `LocalInferenceState::stop()` called from `RunEvent::Exit` hook in `lib.rs`
- Frontend `beforeunload` as secondary defense
- `kill_on_drop(true)` on the `Child` process handle

### Model Registry

Hardcode the curated model list in Rust (similar to Whisper model list). Each entry has a Hugging Face URL, expected file hash, and metadata. This keeps the model list versioned with the app and avoids API calls to discover models.

### Reuse Patterns

| Existing Pattern | Reuse For |
| --- | --- |
| Whisper model downloads (`transcription.rs`) | LLM model download with progress events |
| ACP agent lifecycle (`acp.rs`) | Sidecar process management and cleanup |
| Ollama provider (`ollama.ts`) | `LocalProvider` implementation (same API shape) |
| Recording store (`recording-store.ts`) | Local AI store (mixed persistence pattern) |
| Copilot status bar indicator | Local AI status indicator |
