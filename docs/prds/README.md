# Product Requirements Documents

PRDs are created with `/prd <feature-name>` and saved here as `YYYY-MM-DD-<slug>.md`.

## Conventions

- One PRD per feature or initiative
- File name format: `YYYY-MM-DD-feature-slug.md`
- PRDs are living documents — update as scope evolves
- Reference PRDs from task breakdowns and verification reports

## Template Sections

Each PRD includes:

1. **Problem** — What user pain or gap this addresses
2. **Goals / Non-Goals** — Scope boundaries
3. **User Stories** — Key workflows
4. **Technical Approach** — Architecture and implementation strategy
5. **UI/UX** — Wireframes, interactions, design notes
6. **Data Model** — New types, stores, or schema changes
7. **Dependencies** — Libraries, APIs, or prerequisites
8. **Quality Gates** — How we know it's done
9. **Out of Scope** — Explicitly deferred items
