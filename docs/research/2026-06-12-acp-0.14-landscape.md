# ACP 0.14.0 Landscape — Upgrade Impact, MCP Strategy, and Local Agents

**Context:** `agent-client-protocol` 0.14.0 (schema 0.13.6) shipped 2026-06-05; Notesage pins 0.12.1 (schema =0.13.2). This research audits the upgrade impact against the actual code (not just docs), maps the full protocol landscape vs what Notesage consumes, evaluates whether to keep the in-house MCP client, and surveys the ecosystem for local-model ACP agents. Method: crate sources for 0.12.1/0.13.2 and 0.14.0/0.13.6 downloaded from crates.io and diffed; every Notesage claim verified by grep against `src-tauri/src/commands/acp.rs`, `useAcpLifecycle.ts`, `useAcpSessionListeners.ts`, `AcpSessionControls.tsx`, `mcp.rs`, and stores.

---

## Executive Summary

1. **The 0.14.0 upgrade is a real migration, not a bump.** Three of Notesage's five `unstable_*` feature flags no longer exist (build fails if kept). The session **model** API (`SetSessionModelRequest` / `SessionModelState` / `resp.models`) was **deleted from the protocol** — model selection moves to the stable session config-options API (`SessionConfigOptionCategory::Model`). Message IDs were stabilized as a *different* design (agent-assigned `ContentChunk.message_id`; the client-supplied `PromptRequest.message_id` + `user_message_id` echo were removed). Session **modes** (Plan/Ask/Agent picker) are untouched.
2. **Sitting on 0.12.1 decays silently.** As shipped agents track the spec they will stop emitting the unstable `models` field and stop answering `session/set_model` — the connection-level model application degrades with no compile error. The upgrade converts a future silent regression into compiler-checked work.
3. **Notesage's MCP client is display-only.** No AI path can call an MCP tool: `getToolDefinitions()` merges only built-ins + skill tools; ACP sessions pass no `mcp_servers`; the sole `mcp_call_tool` consumer is the settings validation preview. ~2,800 lines of Rust (`mcp.rs` + `mcp_oauth.rs`) currently deliver registration/validation/listing only.
4. **Recommended MCP strategy: delegate to agents (Option B).** Pass `mcp_servers` at `session/new`; agent-spawned stdio servers inherit the agent's Seatbelt sandbox + network deny *by process inheritance*, closing the per-server-sandbox gap deferred in the 2026-06-09 audit for free. Direct-API MCP wiring (Option A) stays an explicit revisit trigger, not a commitment.
5. **Local models can act as agents today via ecosystem ACP agents** — OpenCode (`opencode acp`) and Qwen Code (`qwen --experimental-acp`) run as stdio ACP agents against local OpenAI-compatible endpoints, i.e. the bundled llama-server. No "acp_local_agents" library exists (and searches collide with IBM's unrelated *Agent Communication Protocol*); the gap is covered by these agents, by agent-side SDKs (Rust/TS/Python; Mastra exposes agents over ACP), and eventually by the protocol's `unstable_llm_providers` API. This motivates PRD [local-ai-agents](../prds/2026-06-12-local-ai-agents.md).

## Breaking Changes and Flag Reshuffle

| Flag Notesage enables (0.12.1) | Status in 0.13.6 | Action |
| --- | --- | --- |
| `unstable_session_model` | **API removed** (0.13.5) — no stable v1 replacement; config options `category: Model` is the path | Delete flag; migrate (see below) |
| `unstable_message_id` | **Removed** — stabilized as chunk-side IDs (0.13.6) | Delete flag; redesign (see below) |
| `unstable_session_usage` | **Removed** — `UsageUpdate` stabilized (0.13.6) | Delete flag; listener keeps working |
| `unstable_auth_methods` | Still unstable, still exists | Keep (EnvVar auth — Gemini) |
| `unstable_session_fork` | Still unstable, still exists | Keep (branch forking) |

**Session model migration.** Removed: `SessionModelState`, `SetSessionModelRequest`, `ModelId`, `models` field on session responses. Affected code: `acp.rs` (~737/784/1001 `resp.models` extraction, ~950 `SetModel`, `acp_session_set_model`, `AgentModelInfo`), `tauri.ts` `acpSessionSetModel`, `useAcpLifecycle.ts` ×3 (applies `connection.config.model` at session create/restore), probe-discovered `availableModels` in `ConnectionCard`. There is **no in-chat model picker** — `AcpSessionControls` has only `AcpModePicker` (modes API, stable, untouched) and `ConfigOptionPicker`. Migration: derive available/current model from the config option with `category == Model`; set via the existing `SetSessionConfigOptionRequest` path; delete the dedicated command. Note the `unstable_llm_providers` API is *not* the replacement — that's BYOK endpoint routing (`providers/set` with `{api_type, base_url, headers}`, `LlmProtocol = Anthropic | OpenAi | Azure | Vertex | Bedrock | Other`).

**Message-ID redesign.** 0.13.2 (unstable): client sends `PromptRequest.message_id`, agent echoes `user_message_id`. 0.13.6 (stable): only `ContentChunk.message_id: Option<MessageId>` survives — agent-assigned, chunks of one message share it, an ID change = new message. Delete outbound plumbing (`acp.rs` 266/821/857 + 2 serde tests; `useAcpLifecycle` 544/670/840; `tauri.ts`); keep the inbound listener (`useAcpSessionListeners` 106-119 already reads `update.messageId`), fix its "echo" comment.

**Newly stable, unadopted:** `session/delete` (stronger than the best-effort close on conversation delete), `logout` (protocol re-auth before the Terminal.app fallback), `additionalDirectories` on `session/new` (tell agents the full multi-project scope the sandbox already grants — today only `cwd` is passed).

**New unstable surface (watch):** `unstable_end_turn_token_usage` (`PromptResponse.usage`), `unstable_plan_operations` (`PlanUpdate`/`PlanRemoved`), `unstable_elicitation`, `unstable_llm_providers`, `unstable_nes`, `unstable_protocol_v2` (v2 drops dedicated modes/models APIs — config options become the universal mechanism; drops SSE; requires chunk message IDs).

## Code-Verified Notesage Surface

Notesage advertises **default `ClientCapabilities`** at initialize: `fs.read_text_file/write_text_file: false`, `terminal: false`. Agents therefore do their own FS (governed by Seatbelt) and Terminal tool-content blocks render as a placeholder. One inbound handler is registered (`RequestPermission`). Session updates handled: message/thought chunks, tool_call(+update/result), turn complete, session_info, current_mode, config_option, plan, usage, available_commands, user_message_chunk. Unadopted client-side surfaces: FS methods (would give agents **unsaved-buffer reads** and scope-gated writes through Notesage), `terminal/*` methods, `mcp_servers` at session/new.

## Docs/Code Drift Found

- **"Chat footer" is dead terminology.** The surface is the floating command bar header/context row (`AcpSessionControls` in `CommandBarContext`). Stale term survives in two *user-visible* settings strings (`AISettings.tsx:141`, `EditorSettings.tsx:307`), ~12 files of comments/test names, and 4+ docs.
- **`architecture.md` isolation table claims MCP injection into the system prompt** (`mcp-store.getActiveTools`) — that wiring does not exist in the chat path (zero non-test consumers).
- Docs describe an ACP model-picker UX that is actually connection-level model application (see above).

## MCP Strategy — Option A vs B

**A — wire the in-house client into the direct-API loop:** merge `getActiveTools()` into `getToolDefinitions()` (prefix `mcp__<server>__<tool>`), route in `tool-executor.ts`, approval-required by default via `ScopedApproval`. Reaches every AI path incl. local models without an agent binary. Costs: own a conformant MCP client forever (spec churn ×2 transports + OAuth); pulls forward the deferred per-server sandbox + proxy-routing work (mandatory once tools are invocable); context-window pressure on local models (50+ tool defs from one server); L effort all-in.

**B — delegate to agents:** pass `mcp_servers` configs at `session/new`; freeze `mcp.rs`/`mcp_oauth.rs` (OAuth becomes a token provisioner injecting `Authorization` headers into `McpServerHttp` configs, or is sunset if only stdio is passed). Agent-spawned stdio servers **inherit the agent's Seatbelt sandbox and kernel network deny** — the audit's deferred MCP-sandbox items solved by construction for this path. Approvals still flow through ACP permission requests. Loses: MCP in direct-API/agent-less-local chats; fine-grained tool-loop control. S effort beyond the pass-through.

**Recommendation: B now, A kept open** behind explicit triggers — `local_bundled`/Ollama users demanding MCP without an agent binary; a flagship feature needing MCP on every path; need for uniform Notesage-owned tool governance. Revisit after the local-agents PRD ships; the PRD narrows B's user-visible gap to "local model without agent binary installed."

## Local-Model ACP Agents — Ecosystem Survey

⚠️ **Acronym collision:** "ACP" also names IBM/BeeAI's *Agent Communication Protocol* (agent-to-agent messaging); most "ACP local agents" search results are that protocol. No dedicated "acp_local_agents" library exists for the Agent *Client* Protocol.

| Option | ACP agent mode | Local models | Notes |
| --- | --- | --- | --- |
| **OpenCode** | `opencode acp` (stdio); in Zed's agent registry | Ollama, LM Studio, any OpenAI-compatible `baseURL` (⇒ bundled llama-server), with tool calling | Strongest candidate; MIT; ~38–40 MB darwin release assets; weekly+ release cadence (argues for managed install over bundling); built-in MCP client |
| **Qwen Code** | `qwen --experimental-acp`; Zed registry | `OPENAI_BASE_URL` → local vLLM/llama-server/Ollama | Gemini CLI fork — ACP surface resembles existing `gemini --acp` integration; env-var config matches Notesage's EnvVar spawn model |
| goose | ❌ reverse direction (goose *consumes* ACP agents as providers) | Yes | Not spawnable as an agent per current docs |
| crush | ❌ no confirmed agent mode | Yes (openai-compat) | Watch |
| Build-your-own | Rust crate (role-symmetric, examples in repo), TS/Python SDKs; **Mastra** exposes its agents over ACP with any AI-SDK provider | By construction | Protocol plumbing is the easy 20%; agent-loop quality is the hard 80% — fallback only |
| `unstable_llm_providers` | Frontier agents pointed at local endpoints via `providers/set` | By construction | Not stable; agent adoption pending; supersedes parts of the preset approach when it lands — keep endpoint wiring agent-agnostic |

Distribution decision: **managed install, not bundling** — upholds the Phase 10 non-goal (bundle bloat, release-cadence mismatch, re-signing); `agent_manager.rs` already does download/version/update/uninstall with progress UI. Full rationale, preset design, and setup-flow UX: see the PRD.
