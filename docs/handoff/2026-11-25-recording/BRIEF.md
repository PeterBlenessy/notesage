# Recording work: findings, new features and the contract (read fully)

Notesage is a Tauri v2 desktop app for macOS (React/TS in `src/`, Rust in `src-tauri/`) with an iOS companion. This batch fixes every finding of a review of the voice-recording feature and adds three capabilities the owner asked for: recording **system audio** as well as the microphone, **importing a video or audio file** (e.g. a Teams meeting recording) to transcribe it, and **merging a Teams transcript** (speaker names) with our own transcript. Four agents work in parallel in separate worktrees; the CONTRACT at the end is binding for all of them. Line numbers are approximate: verify by reading.

The owner records hour-long meetings, in Swedish and English, on a MacBook, with the library in Notesage's iCloud container. Nothing here can be run against audio hardware in this environment (Linux container; `cargo test` cannot link; macOS-only code only compiles). So: keep macOS-specific code small, behind `#[cfg(target_os = "macos")]`, with pure, unit-testable logic separated from the system calls, and list precisely what must be verified on a Mac.

## Findings: capture and storage (Rust; `src-tauri/src/commands/transcription.rs` unless noted)

- **C1 device loss is silent (HIGH).** `:330` opens `default_input_device()`. For the default device cpal replaces the error callback with a no-op and, on device death, pauses the stream (`cpal-0.17.3/src/host/coreaudio/macos/device.rs:813-822`, `macos/mod.rs:147-160`); the app's `err_fn` (`:385`) only logs. The capture thread keeps parking (`:460`), the UI keeps counting. Fix: a "last callback" atomic timestamp checked by the park loop; after ~2 s without callbacks while not stopped/paused, emit a warning event and reopen on the current default device, continuing into the same recording (a new segment file is acceptable if appending is not safe across a format change).
- **C2 write errors discarded (HIGH).** `:405` `let _ = w.write_f32(data);`. Duration comes from `count_cb` (`:424`), not `samples_written`, so a failed write still counts. No free-space check at start (iOS has 200 MB, `Recorder.swift:234`). Fix: surface the first write error, derive duration from samples actually written, check free space at start and periodically.
- **C3 crash/quit leaves an unusable, invisible file (HIGH).** WAV header written with zero sizes (`:115`), patched only in `finalize()` (`:142`); symphonia reads data length 0 as empty. `recording.json` is written by the frontend only after stop (`src/hooks/useMeetingRecording.ts:119`). `RunEvent::Exit` (`src-tauri/src/lib.rs:622-634`) does not stop the recorder. Fix: patch the header periodically (~10 s) from the park loop, stop capture in `RunEvent::Exit`, and recover orphans at startup (see contract).
- **C4 real-time callback does too much (MEDIUM).** Per callback (`:391-440`): a `Vec` allocation (`:128`), an unbuffered `write(2)` (`:134`), four `std::Mutex` locks, `serde_json::json!` + `app.emit("recording-level")` (`:436`, ~94/s, also while paused), with no listener. Fix: callback only pushes samples into a lock-free/bounded SPSC buffer with a dropped-frames counter and updates atomics; the capture thread drains it through a `BufWriter`, computes levels and emits at most 10/s.
- **C5 no permission preflight; silence detected only at stop (MEDIUM).** Only check is `peak < 0.0001` after stop (`:862`). Fix: warn after the first ~5 s of silence; preflight command (contract).
- **C6 system audio is not recorded (HIGH for meetings).** `start_recording` rejects `"system"` (`:769`) and `"both"` silently records the mic (`:774`). cpal 0.17.3 ships a CoreAudio process-tap loopback (`cpal-0.17.3/src/host/coreaudio/macos/loopback.rs`, used when `build_input_stream` is called on an OUTPUT device, `device.rs:754-758`); it needs macOS 14.2+ and `NSAudioCaptureUsageDescription` in Info.plist. Build it (contract).
- **C7 blocking in async commands (LOW).** `start_recording` blocks a tokio worker on `rx.recv()` (`:502`, `:779`); `delete_whisper_model` (`:1305`) and `collect_diagnostics` (`:598`, called from `logging.rs:131`) take the Whisper lock held for a whole transcription. Fix: `spawn_blocking`; `try_lock`.
- **S1 Mac recordings land outside the library (HIGH).** Rust hardcodes `~/Notesage/Recordings` (`:552`); the Recordings view and scanner list `icloudNotesagePath ?? notesRoot` + `/Recordings` (`src/hooks/useRecordingsInbox.ts:465`, `src/stores/recordings-store.ts:121-129`). Fix: record into a LOCAL staging folder, then move the finished bundle into the library's Recordings folder (contract).
- **S2 file size (MEDIUM).** 16-bit PCM at native rate: 345.6 MB/h at 48 kHz mono, 691 MB/h stereo. Phone records AAC at ~29 MB/h. Fix: after stop, produce mono AAC `.m4a` (contract) so iCloud is not syncing hundreds of MB per meeting.
- **S3 evicted audio (MEDIUM).** `file_size` / `icloud_ensure_downloaded` assume `.name.icloud` stubs (`src-tauri/src/commands/file.rs:470-486`, `sync.rs:68-74`); current macOS uses dataless files (exists, full `len()`), so the size gate passes and decoding blocks on materialisation on a tokio worker (`:923`). The index already detects dataless (`src-tauri/src/index/fs_access.rs`). Fix: reuse that detection; request download and wait with a timeout; decode inside `spawn_blocking`.
- **S4 listing cost (LOW).** `scanAll` and `recordings-store.load` call `listDirectory(dir)` with no `maxDepth` then 2 to 3 IPC calls per bundle. Use `maxDepth: 0` (supported since v0.63.0) and batch.
- **S5 file permissions (LOW).** Recordings are created 0644 in a 0755 folder: other local accounts can read them. Create bundles 0700 / files 0600.

## Findings: transcription and models (Rust)

- **T1 memory on long recordings (HIGH).** `decode_with_symphonia` accumulates the whole file as interleaved f32 (`src-tauri/src/commands/audio_decode.rs:153-186`); `resample_to_16k_mono` copies again (`data.to_vec()`, `transcription.rs:706`); `decoded` is never dropped (`:923-934`). 1 h at 48 kHz mono peaks ~1.6 to 1.9 GB before the model. Fix: downmix and resample per packet inside the decode loop so only the 16 kHz mono buffer exists (230 MB/h); at minimum drop `decoded` and avoid the copy.
- **T2 progress frozen at 15% then a burst (MEDIUM).** `full()` (`:1001`) runs to completion before the segment loop (`:1017-1042`) emits ~1,000 events each carrying text. Fix: `params.set_progress_callback_safe` (whisper-rs `whisper_params.rs:575`), emit on integer change only; do not emit per-segment text events.
- **T3 no cancellation (MEDIUM).** Use `set_abort_callback_safe` (`whisper_params.rs:621`) and a cancel command.
- **T4 jobs serialised only at the Whisper lock, after decoding (MEDIUM).** Two jobs each decode fully into RAM. One semaphore at the top of `transcribe_file`; one lock scope for model load + inference (also closes the model-swap race at `:964-988`).
- **T5 accuracy preprocessing (MEDIUM).** 48→16 kHz is linear interpolation with no low-pass (`:709-725`): aliasing into the speech band. No VAD (whisper-rs exposes `set_vad_model_path`, `whisper_params.rs:834`), so long silences produce hallucinations. No gain normalisation. Fix: a proper band-limited resampler (the `rubato` crate may be added for this), peak/RMS normalisation of quiet input; VAD only if it needs no extra model download, otherwise skip silence with a simple energy gate and say what was done.
- **T6 model stays loaded forever (LOW).** Unload after an idle timeout.
- **T7 model download (LOW-MEDIUM).** Plain GET of `resolve/main/...` (`:693`): no SHA-256, no size check, no resume, no read timeout (cancel cannot interrupt a stall, `:1246-1247`), temp file deleted at next launch (`:560-568`), sync `write_all` in the async loop (`:1254`), no free-disk check. Fix: pinned revision + hash (`sha2` is a dependency), `Range` resume, timeout via `tokio::select!`, free-space check.
- **T8 language (LOW-MEDIUM).** Default is the device language (`src/lib/transcription/languages.ts:72-79`), pinned for the file; a Swedish meeting on an English macOS decodes as English. Keep the per-recording override; make the last-used language the default for the next recording; show the language on each recording.
- **T9 docs drift.** `docs/tauri-commands.md:1566` documents `{model, percent}`; payload is `{model, downloaded, total}`.

## New capabilities

- **N1 system audio.** Sources: Microphone, System audio, Both. With Both, the microphone and system audio are captured as SEPARATE tracks, time-aligned to a common start, so the transcript can label "Me" (microphone) and "Others" (system audio) without any voice analysis.
- **N2 import a video or audio file.** The user picks or drops a file (Teams/Zoom `.mp4`, `.mov`, `.m4a`, `.mp3`, `.wav`, `.webm` if decodable); the app extracts the audio into a normal recording bundle in the library's Recordings folder and transcribes it like any other recording. The original video is NOT copied into the library (it can be gigabytes); the bundle records its original file name and path.
- **N3 Teams transcript merge.** The user attaches the transcript Teams produced (`.vtt` download; `.docx` if feasible) to a recording. Its cues carry speaker names and timestamps. The app aligns it to our transcript in time (Teams transcription may have started later than the recording: estimate the offset by matching text) and produces a transcript with real speaker names. Options: keep our text with Teams' names (default), or Teams' text. The Teams file is kept in the bundle.
- **Speakers in general.** Every segment may carry a `speaker` label. Labels come from tracks (N1), from a Teams transcript (N3), or later from voice analysis (not built in this batch). A bundle-level map renames a label to a person's name; renaming one speaker updates the whole transcript.

## CONTRACT (binding; do not deviate without writing the deviation into your CONTRACT-NOTE file early)

Each agent writes `/tmp/claude-0/-home-user-notesage/cd4314aa-c329-5ae6-b17f-f8993da7623e/scratchpad/rec/<agent>/CONTRACT-NOTE.md` as early as possible with the exact shapes it implements, and re-reads the other agents' notes before finishing. Rust structs crossing IPC keep the file's existing serde naming convention (check `transcription.rs`: follow what `stop_recording`'s result does today) and say so in the note.

### Bundle on disk (`<library>/Recordings/<Bundle name>/`)
```
recording.json          manifest (existing; written by the frontend; fields added below)
audio.m4a | audio.wav   the mixed/primary audio that players and single-track transcription use
mic.m4a|.wav            only for source "both": the microphone track
system.m4a|.wav         only for source "both": the system-audio track
transcript.md           human transcript (body only + small frontmatter: title, date, duration, language, model, speakers used)
segments.json           { version: 1, segments: [{ start: number, end: number, text: string, speaker?: string }] } (seconds, relative to the start of audio)
speakers.json           { version: 1, names: { "<label>": "<display name>" } } (optional; labels: "me", "others", "speaker-1"…, or a name from Teams)
teams-transcript.vtt    optional, the attached original (or .docx)
```
Manifest additions (all optional, older bundles lack them): `source: "microphone" | "system" | "both" | "import"`, `tracks: [{ role: "mic" | "system" | "mix", file: string }]`, `originalFile: { name: string, path: string }` (imports), `title: string` (user-given name; the bundle folder name stays stable), `language: string`.
Reading must tolerate old bundles: `audio.wav` only, segments in `transcript.md` frontmatter (read them from there when `segments.json` is absent; never rewrite an old transcript just because it was opened).

### Recording commands (Rust owner: agent `capture`)
- `recording_preflight(source) -> { microphone: "granted" | "denied" | "undetermined" | "unknown", system_audio: "available" | "unsupported" | "denied" | "unknown", input_device: string | null, output_device: string | null, free_bytes: number }`. "unsupported" = macOS older than 14.2 or non-macOS. Must not prompt for permission by itself.
- `start_recording(source: "microphone" | "system" | "both") -> <existing result shape>`. Records into a LOCAL staging bundle `~/.notesage/recordings-staging/<Bundle name>/` (never iCloud). If `source` includes system audio and it is unavailable or denied, fail with a clear error; never silently record less than asked.
- `pause_recording`, `resume_recording`: unchanged.
- `stop_recording() -> { bundle_dir: string (staging), audio_path: string, tracks: [{ role, path }], duration_secs: number (from samples WRITTEN), peak: number, sample_rate: number, dropped_frames: number, warnings: string[] }`. Finalises WAV headers, then (macOS) encodes to AAC `.m4a` and removes the WAV only after the encode is verified (non-zero duration close to the WAV's); on any encode failure keeps the WAV and returns it. `audio_path` is the mix (for "both": mic + system mixed to mono).
- `discard_recording() -> ()`: stops and deletes the staging bundle.
- `finalize_recording_bundle(staging_dir: string, dest_recordings_dir: string) -> { bundle_dir: string, audio_path: string, tracks: [{ role, path }] }`: moves the staging bundle into `dest_recordings_dir` (create it; atomic rename when on the same volume, else copy, verify sizes, then delete), choosing a non-colliding folder name. The frontend calls it AFTER writing `recording.json` into the staging bundle, so a bundle never appears in the library without a manifest.
- `recover_orphan_recordings() -> [{ bundle_dir (staging), audio_path, tracks, duration_secs, started_at: string | null }]`: finds staging bundles left by a crash/quit, repairs unfinalised WAV headers from the file length, and returns them (it does not encode or move; the frontend then writes manifests and calls `finalize_recording_bundle`). Bundles with no audio data are deleted and not returned.
- `get_recording_state() -> { recording: boolean, paused: boolean, source: string | null, started_at_ms: number | null, elapsed_recorded_ms: number }` (elapsed from samples written, so the UI timer can show recorded time, not wall-clock).
- App exit (`RunEvent::Exit` / window close with quit) stops and finalises any live capture (WAV header at least).
- Events:
  - `recording-level`: `{ mic: number | null, system: number | null }` (peak 0..1 since the last event), at most 10 per second, only while recording and not paused.
  - `recording-warning`: `{ kind: "silence" | "device-lost" | "device-changed" | "write-error" | "low-disk" | "dropped-frames", message: string, fatal: boolean }`. `silence`: no signal above a threshold on a requested source for the first ~5 s, or for 30 s later (once per episode). `device-lost` then `device-changed` when capture resumed on another device. `fatal: true` means the backend has stopped the recording and finalised what it had (the frontend then runs the normal stop path).
- macOS: `NSAudioCaptureUsageDescription` added to the app's Info.plist source (find where `NSMicrophoneUsageDescription` is defined) with a plain sentence.

### Transcription commands (Rust owner: agent `transcribe`)
- `transcribe_file(...)`: keeps its existing arguments and adds optional `job_id: string` and `tracks: [{ role: "mic" | "system", path: string }]`. With `tracks`, each track is transcribed separately and the segments are merged by start time with `speaker: "me"` (mic) / `"others"` (system); without, behaviour is as today. Result: `{ segments: [{ start, end, text, speaker? }], language, duration_secs, ... existing fields }`.
- `transcription-progress` event: `{ job_id: string | null, audio_path: string, stage: "loading" | "decoding" | "transcribing" | "finishing", percent: number (0..100 integer, emitted only when it changes) }`. No segment text in events.
- `cancel_transcription(job_id: string | null, audio_path: string | null) -> boolean`: aborts the matching running or queued job; `transcribe_file` then rejects with the exact string `Transcription cancelled`.
- `import_media(source_path: string, dest_recordings_dir: string) -> { bundle_dir: string, audio_path: string, duration_secs: number, original_name: string }`: extracts the audio of a video/audio file into a new bundle folder named `Import <original stem> <YYYY-MM-DD HHMMSS>` (sanitised), as `audio.m4a` when the source's audio stream can be copied or encoded on macOS, else a 16 kHz mono `audio.wav`. Does not copy the video. Runs off the async workers, streams (never holds the decoded file in memory), emits `import-progress` `{ source_path, percent }`. Fails with a clear message for a file with no audio track or an unsupported container, creating nothing.
- Model download events/commands keep their names; `model-download-progress` payload stays `{ model, downloaded, total }` (`total` may be 0/unknown).
- `file_size` (or a new `audio_file_status(path) -> { exists, size, local: boolean }`) reports dataless files as not local; the frontend uses it to show "Downloading from iCloud…".

### Frontend modules (owners in each agent's prompt)
- `src/lib/transcription/segments.ts` (owner: agent `library`): read/write `segments.json` and `speakers.json`, with fallback to legacy frontmatter segments; `renderTranscriptBody(segments, speakers, opts)` producing paragraphs grouped by speaker turn, each turn starting with `**<name>** [hh:mm:ss]` when speakers exist, or a timestamp marker every ~60 s otherwise.
- `src/lib/transcription/teams-transcript.ts` (owner: `library`): `parseTeamsVtt(text) -> Cue[]` (`{ start, end, speaker, text }`), `estimateOffset(ourSegments, cues) -> { offsetSecs, confidence }`, `assignSpeakers(ourSegments, cues, offsetSecs) -> Segment[]`. Pure, heavily tested.
- `src/stores/recording-store.ts` (owner: agent `control`): live recording state (source, levels in a ref-like non-rendering channel, warnings, recorded elapsed), settings (default source, last-used language).
- `src/hooks/useMeetingRecording.ts` (owner: `control`): start/stop/discard/recover flow: preflight → start → … → stop → write manifest into the staging bundle (using the existing manifest helpers in `src/lib/transcription/bundle.ts`, owner `library`: `control` may call them and add the new optional fields through a helper `library` exposes named `writeRecordingManifest(bundleDir, fields)`; if it does not exist yet in your worktree, write the manifest with the existing helper and note it) → `finalize_recording_bundle` into the library's Recordings dir (`icloudNotesagePath ?? resolveNotesRoot(notesRootPath)` + `/Recordings`, the same expression the scanner uses) → start transcription with `tracks` when present.
- The activity-store transcription task and `useTranscriptionJob.ts` (owner: `library`): progress by `job_id`, cancel, no per-segment updates, primitive selectors.
- i18n: every agent adds its own keys to `src/lib/i18n.ts` (English and Swedish), adding only, next to related keys. Namespaces: `recording.*` (control), `recordings.*` and `transcription.*` (library). There is a ceiling test for untranslated strings (`src/lib/__tests__/i18n-coverage.test.ts`); lowering the count is expected: if its "ceiling is stale" check asks for a lower CEILING, the COORDINATOR will set it after merging; do not edit that constant yourself (report the count you measured for your files with `node scripts/i18n-audit.mjs <dir>`).
