## Summary

**15 tasks: 15/15 done — 3S, 8M, 4L**

### Implementation order

1. **Backend foundation** (#1–#5): Rust managed state, model registry, downloads, sidecar lifecycle, streaming proxy
2. **Frontend state** (#6–#8): Zustand store, provider class, connection type registration
3. **Lifecycle hooks** (#9–#10): Auto-start/stop, crash recovery, exit cleanup
4. **UI** (#11–#14): Settings panel, first-run prompt, status indicators, chat footer badge
5. **Polish** (#15): End-to-end testing and quality gates

### Risks & open questions

- **Sidecar binary sourcing:** Need to decide whether to download llama-server binaries in CI from GitHub Releases or commit them to the repo. CI download is cleaner but adds a build dependency on GitHub availability.
- **Model URL stability:** Hugging Face URLs for GGUF models change when repos are reorganized. Hardcoded URLs need a maintenance plan.
- **Port conflicts:** Ephemeral port binding avoids conflicts, but llama-server may not support binding to port 0. May need to probe for an open port.
- **Streaming integration:** The existing `ai_chat_stream` Rust command handles Ollama streaming directly. For local AI we can either reuse that path (treat local as Ollama endpoint) or add a new streaming path. Reusing Ollama's path is simpler.

### #4 — Add llama-server sidecar lifecycle commands ✅ DONE

**Description:** Implement `start_local_server` and `stop_local_server` commands. The server is spawned as a child process using Tauri's sidecar API. It binds to a dynamically assigned port and serves the OpenAI-compatible API. Add `get_local_server_status` for health checks.

**Acceptance criteria:**

- `start_local_server(model_path, context_length?, gpu_layers?)` spawns `llama-server` with correct args (`--model`, `--port`, `--ctx-size`, `--n-gpu-layers`)
- Port assigned by probing for an available port (start at 8090, increment until free)
- Returns the assigned port number
- `stop_local_server` sends SIGTERM, waits up to 5s, then SIGKILL
- `get_local_server_status` returns `{ running, port, model, memory_usage_bytes }`
- Health check pings `http://localhost:{port}/health`
- Process handle stored in `LocalInferenceState` with `kill_on_drop(true)`
- Emits `local-server-status` event on state changes
