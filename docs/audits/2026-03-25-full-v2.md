## 1. Memory Leaks & Resource Cleanup

### HIGH: useSpeechRecognition — Race Condition on Web Speech API Fallback

**File:** `src/hooks/useSpeechRecognition.ts:147-156`

When Web Speech API errors with `service-not-allowed`, `startWhisperDictation()` is called recursively without awaiting. The nested listener setup can overwrite the outer listener's `unlistenRef.current`, leaving the original listener active indefinitely.

**Fix:** Await the recursive call and add a mounted guard after the await.

### MEDIUM: useDirectApiChat — Sequential Listener Await Race

**File:** `src/hooks/useDirectApiChat.ts:125-173`

Four listener promises are awaited sequentially. If one throws after others succeed, the remaining listeners won't be cleaned up.

**Fix:** Use `Promise.all()` to await all four `listen()` calls atomically.

### MEDIUM: useSpeechRecognition — Rapid Toggle Overwrites Listener

**File:** `src/hooks/useSpeechRecognition.ts:68-96`

If `startWhisperDictation` is called rapidly before the first `listen()` promise resolves, the second call's unlisten overwrites the first's without cleanup.

**Fix:** Await `listen()` and check `mountedRef.current` before storing the new unlisten.

### LOW: useMcpDiscovery — Listener Callback Not Mount-Guarded

**File:** `src/hooks/useMcpOperations.ts:140-163`

The `mcp-server-status` listener callback doesn't check `mounted` flag. Events arriving during unmount trigger unnecessary store updates. Not a resource leak, but unnecessary work.

**Fix:** Add `if (!mounted) return;` at top of listener callback.

### Confirmed Good Patterns

- `useSandboxViolations` — Now has correct mounted flag + then-guard pattern
- `useRecording` — Level listener properly cleaned up
- `useLocalCompletion` — AbortController for in-flight requests
- `useFileWatcher` — Debounce map overflow guards (MAX_DEBOUNCE_ENTRIES)
- `useAppLifecycle` — File-open event listener with proper cleanup
- Rust process management — `kill_on_drop(true)`, `RunEvent::Exit` hooks, orphan cleanup all excellent

## 2. Async Flows & Race Conditions

### HIGH: ACP Agent Singleton Race Condition

**File:** `src/lib/ai/acp-agent-state.ts:43-77`

Module-level `acpAgent` is a mutable singleton. Multiple concurrent calls to `ensureAcpAgent()` can both read null and both spawn — one agent is leaked.

**Fix:** Use a per-connection `Map<connectionId, Promise>` for deduplication instead of a global null check.

### HIGH: Task Agent Singleton Race Condition

**File:** `src/hooks/useAgentTaskOperations.ts:55-141`

Same pattern as ACP agent. `taskSpawnPromise` partially mitigates but doesn't prevent overwrites from different connection IDs.

**Fix:** Same per-connection deduplication approach.

### MEDIUM: useModelMetadata — fetchedRef Never Resets

**File:** `src/hooks/useModelMetadata.ts:8-48`

Once `fetchedRef.current = true`, it never resets. If models change after remount, the fetch is skipped.

**Fix:** Reset `fetchedRef` when `models` dependency changes.

### MEDIUM: useLocalAI — Promise.all Loses All Results on Single Failure

**File:** `src/hooks/useLocalAI.ts:41`

If any of three promises (memory, models, binary) fails, `Promise.all` rejects the entire batch — successful results are lost.

**Fix:** Use `Promise.allSettled` and handle individual failures.

### MEDIUM: useSkillDiscovery — Missing Outer Error Boundary

**File:** `src/hooks/useSkillOperations.ts:196-244`

Async IIFE without outer error handling. If `migratePersonasToAgents()` or `scanSkills()` throws, the error is swallowed and skills/agents don't load.

**Fix:** Add `.catch()` with `toast.error()` for user visibility.

### MEDIUM: useLocalCompletion — Editor Null Check After Await

**File:** `src/hooks/useLocalCompletion.ts:140-141`

After async completion request, editor reference may be stale (user switched tabs). Ghost text could be inserted into the wrong tab.

**Fix:** Capture editor instance at request time and validate it hasn't changed after await.

### MEDIUM: useFileWatcher — Stale State in Debounced Modify Handler

**File:** `src/hooks/useFileWatcher.ts:217-278`

`handleModifyEvent()` reads store state after awaits. Between reads, tab state could have changed, making logic fragile.

**Fix:** Capture all required state before async operations and validate consistency.

### Confirmed Good Patterns

- `useCommentOperations` debounce correctly captures values before setTimeout
- `useCopilotCompletion` version tracking properly discards stale responses
- ACP session listeners cleanup has re-entrancy guard
- `useAppLifecycle` mounted guard checked after every await
- Rust `AcpState` properly uses `Mutex<HashMap>` for thread-safe agent management

## 3. Render Performance & Zustand Patterns

### HIGH: ChatPanel — 18 Store Subscriptions Without Granular Selectors

**File:** `src/components/chat/ChatPanel.tsx:51-88`

ChatPanel subscribes to 18 fields from `useChatStore` — any mutation to any field triggers a full re-render of the entire chat panel, including message list, input, footer controls.

**Fix:** Split into memoized sub-components (ChatMessageList, ChatFooter, ChatHistoryView) with individual selectors. Use `React.memo()` on sub-components.

### HIGH: Sidebar — 11 Fields from useWorkspaceStore

**File:** `src/components/sidebar/Sidebar.tsx:27-38`

Every workspace state change (file tree update, collapse toggle, project addition) triggers a full re-render of all three sidebar sections.

**Fix:** Split into `QuickNotesSection`, `ProjectsSection`, `FoldersSection` with `React.memo()` and granular selectors.

### HIGH: FileTreeItem — Recursive Items with 13+ Store Subscriptions

**File:** `src/components/sidebar/FileTreeItem.tsx:69-94`

Each FileTreeItem subscribes to 6 stores (workspace, editor, external-change, settings, project-metadata, git). For large folder trees, this cascades to hundreds of re-renders per store update.

**Fix:** Wrap in `React.memo()` with custom comparator. Extract expensive computations into a hook returning stable references.

### MEDIUM: Layout.tsx — Inline Callbacks with getState() Anti-Pattern

**File:** `src/components/Layout.tsx:170-182`

`useCallback` with empty deps + `getState()` creates stale closures. Pattern hides dependencies from React.

**Fix:** Use proper selectors and include all dependencies in `useCallback`.

### MEDIUM: CommandPalette — useMemo Defeated by Unstable Dependencies

**File:** `src/components/CommandPalette.tsx:276-289`

Toggle callbacks reference `.getState()` to avoid declaring selector dependencies, but this defeats the memoization of the actions list.

**Fix:** Use proper selectors and stable callback references.

### MEDIUM: DocumentOutline — Inline onClick Per Heading

**File:** `src/components/DocumentOutline.tsx:80-95`

Each heading button creates inline callbacks per render. Currently mitigated by using `data-pos` attribute delegation — acceptable but not optimal.

### MEDIUM: Cross-Store getState() Calls

**Files:** `src/stores/action-store.ts:59-77`, `src/stores/routing-store.ts:60,75,87`

Multiple stores reach into other stores via `getState()`. Not a cycle but creates tight coupling and potential stale reads.

### Confirmed Good Patterns

- `TitleBar.tsx` — Proper individual selectors on multiple stores
- `ChatPanel.tsx` — Smart array stabilization with ref + useMemo for project paths
- `useAIOperations.ts` — Well-structured multi-step memoization
- `SidebarPanel.tsx` — Good useCallback dependency management

## 5. Rust Backend

**No issues found. All previous findings resolved:**

- Double keychain read → Fixed (single `make_entry()` call)
- Panic on tokio runtime → Fixed (errors sent via `init_tx` channel)
- Silent try_lock → Fixed (logged with `warn!()`)
- HTTP client per request → False positive (uses `LazyLock<reqwest::Client>`)

### Confirmed Good Patterns

- Process management: `kill_on_drop(true)`, ordered cleanup in `RunEvent::Exit`, orphan recovery via `pkill`
- Mutex discipline: Correct `tokio::sync::Mutex` in async, `std::sync::Mutex` in sync contexts, no nested locks
- SQL safety: All queries use parameterized `rusqlite::params!`
- No unsafe code in commands module
- All shared mutable state in `Mutex`, `Arc<AtomicBool>` for flags
- JSON-RPC transport shared via `json_rpc.rs` (no duplication)
- Credential storage in OS keychain, never in IPC or logs

## 6. Security

**No vulnerabilities found.** The security posture is excellent:

- **SQL injection:** All queries parameterized; FTS5 properly escaped via `build_fts_query()`
- **XSS:** DOCX content sanitized with DOMPurify; editor content validated through ProseMirror
- **Credentials:** OS keychain via `keyring` crate; keys never in localStorage, IPC, or logs
- **Command injection:** All subprocess args passed as arrays, never shell-concatenated
- **Path traversal:** Canonical path validation in script execution; Tauri capabilities restrict filesystem
- **Network sandbox:** Kernel-enforced `(deny default)` + proxy filtering + user approval + violation monitoring
- **Defense-in-depth recommendation:** Add DOMPurify sanitization in `ai-suggestion.ts` and `external-diff.ts` as boundary layer for markdown-to-HTML paths

## 7. Type Safety

**Counts:** 12 `as any` casts, 8 `as unknown as T` double casts, 5 `: any` annotations, 0 `@ts-ignore`/`@ts-expect-error`

### HIGH: Rust Provider Type as String

**File:** `src-tauri/src/commands/ai.rs`

Provider names (`"anthropic"`, `"openai"`, `"ollama"`) dispatched via `match provider.as_str()`. Typos in frontend calls silently fall through to `_ =>` error handler.

**Fix:** Create `#[derive(Serialize, Deserialize)] enum AIProviderType` with `#[serde(rename_all = "snake_case")]`.

### HIGH: Tiptap Editor Storage `as any` (3 instances)

**Files:** `src/hooks/useEditorTabSwitch.ts:100,215`, `src/hooks/useEditor.ts:39`

`editor.storage` cast to `any` to access extension-specific properties. Tiptap doesn't expose typed storage.

**Fix:** Define typed wrapper interfaces for each extension's storage shape.

### MEDIUM: AI Suggestion Functions Accept `editor: any` (3 instances)

**File:** `src/components/editor/extensions/ai-suggestion.ts:244,254,293`

Public exported functions `setSuggestion()`, `clearSuggestion()`, `rejectSuggestion()` accept `editor: any`.

**Fix:** Change to `editor: Editor` from `@tiptap/core`.

### MEDIUM: Web Speech API Casts (4 instances)

**File:** `src/hooks/useSpeechRecognition.ts:117-118,123,194`

Web Speech API not in TypeScript DOM types. Uses `(window as unknown as Record<string, unknown>)`.

**Fix:** Create typed Web Speech API shim with proper `SpeechRecognition` interface.

### MEDIUM: foliate-js EPUB Viewer Double Casts (4 instances)

**File:** `src/components/editor/viewers/EpubViewer.tsx:248,263,306,311`

Web Component `<foliate-view>` requires double casting. Unavoidable for Web Components but could be better encapsulated.

### MEDIUM: Rust Event Names and Model IDs as Strings

**Files:** Various hooks and commands

Event names (`"acp-session-update"`, `"dictation-result"`) and model IDs dispatched as string literals. Typos cause silent failures.

**Fix:** Create typed event system and model ID enums.

### LOW: Tauri Storage Generic Hardcoded to `any`

**File:** `src/lib/tauri-storage.ts:169`

`createJSONStorage<any>()` should be `<T = unknown>()`.
