## Methodology

For each leak in the consolidated inventory:

1. **Locate the fix** — trace the leak → task number → commit(s).
2. **Verify the code change** — read the current state of the enforcement site; confirm the audit's named line range now contains the fix, not the leak shape.
3. **Verify the regression-lock** — locate the red-team attack test that codifies the invariant. The expectation is: one or more tests that would have passed against the *pre-fix* code (proving leak was real) and now assert the attack path is refused.
4. **Mark result** — "no longer reproducible" or "still reproducible (regression)."

A full manual attempted-repro against a running app was not performed for every leak. Instead, the red-team TDD discipline (codified in the task breakdown and followed by every implementing agent) means each Critical / High leak has an invariant test in the suite that would fire if the leak re-opens. `pnpm vitest run` = 3106/3106 green. `cargo test sandbox::` = 28/28. `cargo test --test sandbox_isolation -- --ignored` = 3/3 kernel-level deny tests (last verified during #6c/#6d development).

Two regressions surfaced *during this verification cycle itself* (documented in §5 below) — proof that the discipline catches real issues.

## Regressions found DURING verification

Two real bugs surfaced while the red-team was under way. Each is a demonstration that the discipline works — and that it wasn't a paper exercise.

### R1: `agent_config_entries` basename bug (2026-04-19 evening)

- **Symptom:** Claude / Codex / Copilot all failed at session/new with EPERM on their config files. Gemini worked.
- **Root cause:** `acp.rs:run_agent_thread` passes the resolved absolute path (`/opt/homebrew/bin/copilot`) to `sandboxed_command`, but `agent_config_entries` matched against the bare command name. Every absolute-path caller fell into the `_` arm, silently stripping Bucket C.
- **Fix:** `081f535` — `Path::file_name()` extracts the basename before matching. Regression lock: `agent_config_entries_resolves_absolute_paths` with all four agents at their production paths.
- **Observation:** The original #24 unit tests passed because they fed bare command names. The integration-path mismatch only surfaced in a live spawn. *A manual red-team run on live agents would have been required to catch this even with perfect unit tests.*

### R2: Claude OAuth token in macOS keychain (2026-04-19)

- **Symptom:** After R1's fix, Claude Code's session/new succeeded but session/prompt returned `code -32000 "Authentication required"`.
- **Root cause:** Claude Code's SDK reads OAuth tokens from the macOS login keychain via node-keytar at session/prompt time. The `#6d` allow-list only re-allowed `Library/Keychains/login.keychain-db` for Copilot.
- **Fix:** `3f11205` — added the same narrow literal allow for `claude-agent-acp`. Regression lock: `agent_config_entries_claude_includes_keychain`.

### R3: User messages missing `connectionId` (2026-04-20)

- **Symptom:** Resend/edit dialog never fired, even on provider mismatch.
- **Root cause:** Only assistant messages were stamped with `connectionId`. User messages weren't — but the dialog checks the user message.
- **Fix:** `253470a` — stamp `effectiveConnection.id` on the user message at creation in both `useDirectApiChat.ts` and `useAcpLifecycle.ts`. Regression test added in `useDirectApiChat.test.ts`.

## Conclusion

All 24 leaks from the 2026-04-18 audit are no longer reproducible at the point of this red-team pass. Every Critical and High leak has at least one permanent regression-lock test in the suite (most have multiple). The Track 1 red-team TDD discipline worked: we found R1–R3 in live testing, not months later in the field.

### No follow-up tasks required for the original inventory

All 24 leaks closed. Two UX follow-ups surfaced during testing (tray grouping by project, editor-tab ↔ chat-footer coupling discoverability) and are captured in `docs/audits/2026-04-20-isolation-followups.md`. Those are polish, not security.

### Residual limitations (documented, acknowledged)

- **Sibling-path readability** — #6d closes the leak for projects at `~/Code/A` vs `~/Code/B` by switching to an allow-list model. New agent versions may add path dependencies we haven't enumerated; the allow-list needs to grow with upstream agent updates. Observability PRD (`docs/prds/2026-04-19-agent-sandbox-observability.md`) captures the path forward.
- **Export-time cross-scope reads** (Scenario T, pre-existing) — a malicious markdown file referencing `![](../../../.aws/credentials)` still has bytes embedded in PDF/DOCX output. Acknowledged in the original audit. Not strictly a project-isolation issue; filed as a separate follow-up.
- **Auto-approval default for read-only tools** — `web_search`, `read_skill_content`, `list_directory`, `read_file` are auto-allowed by default (scope-gated, but no permission card). Users can opt into "require confirmation for all tool calls" via the Settings toggle. Acknowledged design trade-off.
