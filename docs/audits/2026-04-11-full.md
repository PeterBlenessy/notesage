## 1. Memory Leaks & Resource Cleanup

### HIGH: useLocalAI — Listener Cleanup Race Condition

**File:** `src/hooks/useLocalAI.ts:218`

The cleanup function awaits the `unlisten` Promise in the cleanup handler (`return () => { unlisten.then((fn) => fn()); }`), which can fail if the component unmounts before the listen Promise resolves. This is inconsistent with the correct mounted-flag pattern used elsewhere (useSandboxViolations, useRecording).

**Fix:** Replace with the mounted flag pattern:

```typescript
let unlistenFn: (() => void) | null = null;
let mounted = true;
listen<...>((event) => {
  if (!mounted) return;
  // handler
}).then((fn) => {
  if (mounted) { unlistenFn = fn; }
  else { fn(); }
});
return () => { mounted = false; unlistenFn?.(); };
```

### MEDIUM: useAcpLifecycle — Cancel Escalation Listener Not Cleaned on Unmount

**File:** `src/hooks/useAcpLifecycle.ts:630-673`

The cancel escalation listener is set up inside a callback (acpCancelChat), not in a useEffect. If a user cancels a prompt and unmounts the hook before the 5-second timeout expires, the listener remains active.

**Fix:** Add a useEffect that cleans up pending escalation timers and listeners on unmount.

### Confirmed Good Patterns

- useDirectApiChat: Properly awaits all listeners in Promise.all() — **FIXED** from previous audit
- useSandboxViolations: Perfect mounted flag pattern
- useRecording: Mounted flag guards re-entrant cleanup
- useLocalCompletion: AbortController for in-flight requests
- useFileWatcher: Debounce map overflow guards (MAX_DEBOUNCE_ENTRIES)
- All Rust processes: kill_on_drop(true), RunEvent::Exit hooks, orphan cleanup

## 2. Async Flows & Race Conditions

### HIGH: useCopilotChat — conversationIdRef "pending" Sentinel Race

**File:** `src/hooks/useCopilotChat.ts:560-575`

When `conversationIdRef.current = 'pending'` is set, if an error occurs during `copilotLspConversationCreate`, the ref resets to null. But if another `sendChatMessage` call checks the ref between error throw and catch execution, a duplicate conversation creation can occur.

**Fix:** Add a cleanup effect that resets conversationIdRef to null on unmount to prevent stale "pending" sentinels.

### MEDIUM: ACP Agent Spawn Race — Concurrent ensureAcpAgent Calls

**File:** `src/lib/ai/acp-agent-state.ts:102-113`

After awaiting `acpSpawnPromise`, the code re-reads `getAcpAgent()` to verify the spawned agent matches the connection. If a third concurrent caller changed the agent, recursion continues. Under high concurrency, `MAX_ENSURE_DEPTH = 3` could be reached spuriously.

**Fix:** Add exponential backoff or a generation ID to distinguish legitimate reconnects from infinite recursion.

### MEDIUM: Module-Level Mutable State Without Atomicity

**File:** `src/hooks/useAgentTaskOperations.ts:42-55` and `src/hooks/useAcpLifecycle.ts:32-48`

When `stopAcpAgent()` clears both `acpAgent` and `acpSpawnPromise`, a suspended `ensureAcpAgent` caller could wake up, read null, then await a stale promise.

**Fix:** Use a single atomic write (version counter or generation ID) so readers detect stale results.

### MEDIUM: Missing Listener Cleanup on Direct API Stream Error

**File:** `src/hooks/useDirectApiChat.ts:376-458`

If an exception is thrown inside a listener callback (before cleanup is called), listeners remain registered.

**Fix:** Wrap each listener callback in a try-catch or guard with the `cancelled` flag.

### MEDIUM: Post-Completion Callback on Stale Task

**File:** `src/hooks/useAgentTaskOperations.ts:406-449`

`onComplete()` and `onError()` callbacks fire even if the task was cancelled or removed from `tasksMap`.

**Fix:** Guard all callback invocations with `if (tasksMap.has(taskId))`.

### MEDIUM: Pending Permission Requests Not Cleared on Error

**File:** `src/hooks/useAcpLifecycle.ts:417-437`

If permission requests were added before an error and retry fails, stale permissions remain in the store.

**Fix:** Add `usePermissionStore.getState().clearRequestsForInstance(instanceId)` in the final catch block.

### MEDIUM: Task Completion Called Twice for ACP Tasks

**File:** `src/hooks/useAgentTaskOperations.ts:339-359`

Both the `acp-session-update` listener (`agent_turn_complete`) and the `acpSessionPrompt` promise resolution can fire `onComplete` at nearly the same time.

**Fix:** Use a `let completionFired = false` flag to ensure only one path executes.

### MEDIUM: Missing Conversation ID Filter in generateText (Copilot)

**File:** `src/hooks/useCopilotChat.ts:107-122`

The `generateText` callback registers listeners without conversation ID filtering (unlike `sendChatMessage` which has `isOurEvent()`). Concurrent calls can mix chunks.

**Fix:** Add a conversationId filter similar to `isOurEvent()`.

### LOW: Unawaited Import in Event Listeners

**File:** `src/hooks/useAgentTaskOperations.ts:353-355`

Fire-and-forget `import('@/lib/notifications').then()` calls silently swallow failures.

**Fix:** Log failures: `.catch((e) => log.warn('notifications', 'Failed to import', e))`.

### LOW: Missing Abort for Inline ACP Task

**File:** `src/hooks/useAcpLifecycle.ts:201-277`

`acpGenerateText` invokes `acp_session_prompt` without cancellation mechanism.

**Fix:** Add AbortController or mount check before resolving.

### Confirmed Good Patterns

- Listener cleanup with refs (useDirectApiChat `cleanupRef`)
- Dedup with in-flight promises (acp-agent-state, useAgentTaskOperations)
- Status guards in event listeners (`if (!current || current.status !== 'running') return`)
- Promise.allSettled for multi-listener setup
- Conversation ID latching in useCopilotChat (`isOurEvent()`)
- Capture stable IDs in callbacks (commentId at top of chain)

## 5. Rust Backend

### MEDIUM: Lock Held Across .await in ACP Commands

**File:** `src-tauri/src/commands/acp.rs` (lines 938-960, 1113-1135, 1176-1210)

```rust
let agents = state.agents.lock().await;
let handle = agents.get(&instance_id)...?;
handle.cmd_tx.send(AgentCmd::...).await?;  // Lock HELD during .await
drop(agents);
```

If the mpsc channel's send buffer is full, the async operation blocks while holding the mutex lock, creating contention for other tasks checking agent status.

**Fix:** Clone the sender and release the lock before sending:

```rust
let cmd_tx = {
    let agents = state.agents.lock().await;
    agents.get(&instance_id).ok_or_else(|| "...")?.cmd_tx.clone()
};
cmd_tx.send(AgentCmd::...).await?;
```

### Confirmed Good Patterns

- All spawned processes: `kill_on_drop(true)`, RunEvent::Exit handlers, PID tracking
- Proper SIGTERM→SIGKILL escalation in stop_sync()
- OS thread joins with 500ms timeout to prevent hangs
- MCP servers use `.start_kill()` for graceful termination
- No `static mut`, no unsafe outside libc::kill() for process checking
- Vec allocations use `.with_capacity()` where appropriate
- Error messages include operation context and underlying error
