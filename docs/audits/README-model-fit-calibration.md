# Model-fit calibration harness

This harness grounds the **UNCALIBRATED** constants in the hardware-aware model-fit engine (`src-tauri/src/commands/model_fit/engine.rs`) against reality. For each model listed in a manifest it runs the pure `engine::evaluate` estimate (RAM + tok/s) and compares it to a real measurement obtained by spawning the bundled `llama-server` (`measure_model_runtime`) and running a fixed decode workload. It prints a per-model and aggregate error table to stdout, writes a dated markdown report to `docs/audits/<YYYY-MM-DD>-model-fit-calibration.md`, and proposes scaling factors for the engine constants. Because it spawns a real model server, it requires actual downloaded `.gguf` files (e.g. under `~/.notesage/models/llm/`) and real Apple-Silicon hardware — it **cannot** run in CI or a sandbox.

**Run it:** copy `src-tauri/model-fit-calibration-manifest.json`, fill the `hardware` block with this machine's real values and point every `model_path` at a real downloaded `.gguf`, then run `pnpm calibrate:model-fit [manifest.json]` (the manifest argument is optional and defaults to the template). The harness only **proposes** constant adjustments — it never edits `engine.rs`. The operator reviews the proposed scaling factors and applies them to `engine.rs` by hand under task #10, then re-runs to confirm the residual error shrinks.
